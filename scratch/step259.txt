The LLM-Based Software Requirement Quality Analyser is organized into two structurally decoupled, cooperating pipelines. \textbf{Pipeline~1} (Section~\ref{sec:pipeline1}) is an in-situ five-layer analytical engine that operates on an individual requirement within the context of its enclosing Software Requirements Specification (SRS) and produces an audited, reviewable refinement. \textbf{Pipeline~2} (Section~\ref{sec:pipeline2}) is an automated empirical evolution benchmark that validates Pipeline~1 by comparing its independently synthesized proposals against the ground-truth modifications codified in the official \textbf{Final Version of the SRS} ($V_{\text{final}}$ / $V_{N+1}$). The pipelines maintain strict separation of concerns: \texttt{HistoricalEvolutionPipeline} encapsulates an instance of \texttt{RequirementQualityPipeline}, orchestrating it against aligned baseline specifications ($V_N$) without leaking future specification data into the analyzer.

\subsection{Pipeline 1: Five-Layer Surgical Quality Analyzer}
\label{sec:pipeline1}

Pipeline~1 models requirement quality remediation as a staged pipeline: multidimensional scoring, contextual false-positive reasoning, surgical generation, fail-closed verification, and human governance. Every layer implements an explicit \texttt{execute()} contract that returns schema-validated Pydantic structures. Free-form text generation is strictly disallowed across all LLM-interfacing layers. The orchestration flow is depicted in Figure~\ref{fig:pipeline1_flow}.

A requirement enters Pipeline~1 as a \texttt{Requirement} tuple $(\text{id}, \text{type}, \text{section}, \text{text})$ paired with an \texttt{SRSContext} object containing document metadata, domain terminology, a sliding window of neighboring requirements, and applicable regulatory standards. Execution halts immediately if an unhandled runtime fault occurs; the pipeline returns an explicit \texttt{error} status rather than propagating corrupted or fabricated partial outputs.

\subsubsection{Layer 1: Multidimensional Requirement Quality Scoring}
\label{sec:layer1}

\textbf{Purpose.} Layer~1 (\texttt{Layer1DocumentScorer}) assesses the target requirement against seven quality attributes established in ISO/IEC/IEEE 29148: Unambiguity, Completeness, Consistency, Conformance, Correctness, Singularity, and Verifiability/Feasibility.

\textbf{Processing.} The underlying model scores each quality dimension $A_i$ on a continuous scale $S(A_i) \in [0.0, 10.0]$. For any attribute where $S(A_i) < 8.0$, the layer generates an itemized \texttt{Shortcoming} record containing an identifier, the offending text segment, an explanatory rationale, and an assigned severity. To prevent model hallucination of composite metrics, the aggregate requirement quality score $Q_{\text{req}}$ is computed deterministically in the execution runtime rather than generated by the model:
\begin{equation}
Q_{\text{req}} = \sum_{i=1}^{7} w_i \cdot S(A_i), \quad \text{where } \sum_{i=1}^{7} w_i = 1.0, \quad w_i \ge 0.
\label{eq:qreq}
\end{equation}
Default weightings allocate $w_{\text{unambig}} = w_{\text{complete}} = w_{\text{verif}} = 0.20$, and $w_{\text{consist}} = w_{\text{conform}} = w_{\text{correct}} = w_{\text{sing}} = 0.10$. All candidate defects $\mathcal{D}_{\text{L1}}$ are passed forward unconditionally to Layer~2.

\subsubsection{Layer 2: Contextual False-Positive Reasoning}
\label{sec:layer2}

\textbf{Purpose.} Layer~2 (\texttt{Layer2DefectReasoner}) resolves the \emph{Contextual False-Positive Paradox} by determining whether an apparent defect flagged in isolation is resolved by information located elsewhere in the SRS.

\textbf{Processing.} For every $d \in \mathcal{D}_{\text{L1}}$, the layer inspects the glossary, architectural boundaries, and neighboring specifications. If external clauses bound the ambiguity or define missing parameters, the defect is classified as \emph{discarded} with an explicit justification. Otherwise, the defect is classified as \emph{retained}. The contextual False-Positive Suppression Rate (FSR) is defined as:
\begin{equation}
\text{FSR} = \frac{|\mathcal{D}_{\text{discarded}}|}{|\mathcal{D}_{\text{L1}}|}, \quad \text{for } |\mathcal{D}_{\text{L1}}| > 0.
\label{eq:fsr}
\end{equation}
Only the partition $\mathcal{D}_{\text{retained}}$ is forwarded downstream; discarded defects are permanently purged from subsequent generative stages.

\subsubsection{Layer 3: Surgical Refinement Generation}
\label{sec:layer3}

\textbf{Purpose.} Layer~3 (\texttt{Layer3SolutionGenerator}) synthesizes a minimal text edit that resolves $\mathcal{D}_{\text{retained}}$ without altering unaffected specification logic.

\textbf{Processing.} Generation is governed by four invariant prompt constraints: (i) resolve only retained defect identifiers; (ii) preserve domain terminology, entity identifiers, and system names verbatim; (iii) enforce Easy Approach to Requirements Syntax (EARS) structural patterns; and (iv) avoid wholesale requirement reconstruction. The output \texttt{Layer3Output} encapsulates the original text, the proposed refinement, an itemized list of modifications, and the specific defect identifiers addressed.

\subsubsection{Layer 4: Fail-Closed Independent Audit}
\label{sec:layer4}

\textbf{Purpose.} Layer~4 (\texttt{Layer4SolutionValidator}) serves as an adversarial verification critic that audits the proposed refinement before stakeholder exposure.

\textbf{Processing.} The proposed refinement is audited against five fail-closed criteria: Defect Resolution, Absence of New Ambiguities, Absence of Unwarranted Assumptions, Functional Intent Preservation, and Syntactic Conformance. The audit function $\mathcal{V}$ is strictly conjunctive:
\begin{equation}
\mathcal{V}(\text{proposal}) = \bigwedge_{j=1}^{5} c_j \in \{\text{True}, \text{False}\}.
\label{eq:validator}
\end{equation}
If any criterion fails ($c_j = \text{False}$), the proposal is marked unvalidated, triggering a fallback flag that warns downstream reviewers.

\subsubsection{Layer 5: Decision Management and Presentation}
\label{sec:layer5}

\textbf{Purpose.} Layer~5 (\texttt{Layer5HumanDecisionManager}) packages the analytical artifacts into an auditable decision payload. It computes a word-level diff, assembles the chain-of-custody rationale from Layers~1--4, and presents actionable recommendations (e.g., auto-accept, review required, or manual override) to the requirement engineer.

\subsection{Pipeline 2: Empirical SRS Version Evolution Benchmark}
\label{sec:pipeline2}

Rather than benchmarking against subjective human annotators, Pipeline~2 evaluates Pipeline~1 by comparing its independent recommendations against the empirical ground truth codified in the \textbf{Final Version of the SRS} ($V_{\text{final}}$ / $V_{N+1}$). 

\begin{figure}[htbp]
\centering
\includegraphics[width=\columnwidth]{figures/pipeline2_architecture.pdf}
\caption{Pipeline 1 Staged Execution Architecture: Multidimensional ISO 29148 scoring, contextual false-positive suppression, EARS surgical refinement, fail-closed validation, and decision diff packaging.}
\label{fig:pipeline1_flow}
\end{figure}

The benchmark architecture comprises four components:
\begin{enumerate}
    \item \textbf{Structural Document Aligner:} Aligns requirements across document versions via a two-stage cascade: exact identifier mapping over genuine specification keys, followed by normalized Levenshtein content alignment. Unnumbered headings and list items are assigned synthetic identifiers and isolated to prevent erroneous key collisions.
    \item \textbf{Evolutionary Change Classifier:} Classifies ground-truth changes between $V_N$ and $V_{\text{final}}$ into six mutually exclusive categories: Unchanged, Editorial/Textual, Quality Refinement (Ambiguity Resolution, Quantification, Parameterization, Scope Clarification, or Consistency Correction), Functional Scope Change, Added, and Deleted.
    \item \textbf{Pipeline-1 Execution Harness:} Evaluates $V_N$ requirements blindly through Pipeline~1 without providing access to $V_{\text{final}}$.
    \item \textbf{Semantic Correspondence Evaluator:} Assesses semantic alignment between Pipeline~1's proposals and the actual revisions present in $V_{\text{final}}$.
\end{enumerate}

\subsubsection{Semantic Correspondence Evaluation}
\label{sec:correspondence}

To evaluate alignment, the evaluator compares the refinement proposal against the finalized specification text in $V_{\text{final}}$, assigning a three-way correspondence rating:
\begin{itemize}
    \item \textbf{\texttt{MATCHED}} ($\mathcal{R}_{\text{MATCHED}}$): Pipeline~1 independently detected the defect and synthesized a refinement semantically equivalent to the revision codified in the Final Version of the SRS.
    \item \textbf{\texttt{PARTIALLY\_MATCHED}} ($\mathcal{R}_{\text{PARTIAL}}$): Pipeline~1 correctly localized the defect, but proposed an alternative technical resolution compared to the Final SRS.
    \item \textbf{\texttt{NOT\_MATCHED}} ($\mathcal{R}_{\text{NOT\_MATCHED}}$): The proposal has no semantic counterpart in the Final Version of the SRS, or the pipeline failed during execution.
\end{itemize}

\subsubsection{Formal Benchmark Evaluation Metrics}
\label{sec:metrics}

Let $\mathcal{U}$ denote the set of all aligned requirement pairs evaluated between $V_N$ and $V_{\text{final}}$. We define the subset of \emph{active pipeline proposals} as:
\begin{equation}
\mathcal{R}_{\text{prop}} = \left\{ u \in \mathcal{U} \mid \text{Refined}(u) \neq \text{Original}(u) \wedge \text{Status}(u) = \texttt{completed} \right\}.
\end{equation}
Requirements where both Pipeline~1 and the Final Version of the SRS preserved the baseline text without modification constitute true negatives ($\mathcal{U}_{\text{TN}}$):
\begin{equation}
\mathcal{U}_{\text{TN}} = \left\{ u \in \mathcal{U} \mid \text{Refined}(u) = \text{Original}(u) \wedge \text{FinalText}(u) = \text{Original}(u) \right\}.
\end{equation}
Let $\mathcal{H}_{\text{qual}} \subseteq \mathcal{U}$ represent the subset of requirements where the Final Version of the SRS introduced an empirical quality refinement. The benchmark metrics are formulated as follows:

\paragraph{1. Strict Proposal Match Rate ($\text{PMR}_{\text{strict}}$).}
Measures the proportion of active pipeline proposals that directly anticipate the specifications codified in the Final SRS:
\begin{equation}
\text{PMR}_{\text{strict}} = \frac{|\mathcal{R}_{\text{prop}} \cap \mathcal{R}_{\text{MATCHED}}|}{|\mathcal{R}_{\text{prop}}|}, \quad \text{for } |\mathcal{R}_{\text{prop}}| > 0.
\label{eq:strict_match}
\end{equation}

\paragraph{2. Combined Proposal Match Rate ($\text{PMR}_{\text{comb}}$).}
Measures the proportion of proposals achieving either full or partial semantic correspondence with the Final SRS:
\begin{equation}
\text{PMR}_{\text{comb}} = \frac{|\mathcal{R}_{\text{prop}} \cap (\mathcal{R}_{\text{MATCHED}} \cup \mathcal{R}_{\text{PARTIAL}})|}{|\mathcal{R}_{\text{prop}}|}, \quad \text{for } |\mathcal{R}_{\text{prop}}| > 0.
\label{eq:comb_match}
\end{equation}

\paragraph{3. Quality Refinement Recall ($\text{QRR}$).}
Measures the pipeline's ability to discover and remediate the genuine quality defects that were historically resolved in the Final Version of the SRS:
\begin{equation}
\text{QRR} = \frac{|\mathcal{R}_{\text{prop}} \cap \mathcal{H}_{\text{qual}} \cap \mathcal{R}_{\text{MATCHED}}|}{|\mathcal{H}_{\text{qual}}|}, \quad \text{for } |\mathcal{H}_{\text{qual}}| > 0.
\label{eq:qrr}
\end{equation}

\paragraph{4. Quality Refinement Precision ($\text{QRP}$).}
Measures the fraction of active pipeline proposals that correspond to genuine quality refinements observed in the Final SRS:
\begin{equation}
\text{QRP} = \frac{|\mathcal{R}_{\text{prop}} \cap \mathcal{H}_{\text{qual}} \cap \mathcal{R}_{\text{MATCHED}}|}{|\mathcal{R}_{\text{prop}}|}, \quad \text{for } |\mathcal{R}_{\text{prop}}| > 0.
\label{eq:qrp}
\end{equation}

\paragraph{5. Overall Evolutionary Agreement ($\text{OEA}$).}
Quantifies system-wide decision fidelity across both active refinements and unmodified specifications relative to the Final SRS:
\begin{equation}
\text{OEA} = \frac{|\mathcal{R}_{\text{prop}} \cap \mathcal{R}_{\text{MATCHED}}| + |\mathcal{U}_{\text{TN}}|}{|\mathcal{U}|}.
\label{eq:oea}
\end{equation}
By isolating $\mathcal{R}_{\text{prop}}$ from $\mathcal{U}_{\text{TN}}$, these formulations prevent passive specification stability from inflating the evaluated proposal precision, while ensuring all rate metrics remain strictly bounded within $[0.0, 1.0]$.
